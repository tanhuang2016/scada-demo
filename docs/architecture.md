# 系统架构

## 总体结构

```text
device-simulator  ──IEC 104──►  master-server  ──内部通道──►  qt-client
     (子站)              (主站)                      (监控与配置)
                              │
                              ▼
                           MySQL
```

- **设备侧**：IEC 60870-5-104（默认端口 **2404**），模拟 RTU/配电终端。
- **主站侧**：读 MySQL 设备/测点配置 → 建链 → 采集 → 告警判定 → 历史入库 → 推送 Qt。
- **Qt 侧**：设备与测点维护、实时监控、告警、曲线、操作日志、模拟登录；本地 **SQLite** 仅存界面偏好（非业务库）。
- **Qt 界面**：布局以 `qt-client/ui/*.ui`（Designer）为主，逻辑在 `src/pages/` 与 `src/net/`。

## 三个程序

| 程序 | 职责 |
|------|------|
| `device-simulator` | 监听 2404；周期上送电压/电流/开关；响应遥控合闸/分闸 |
| `master-server` | 加载配置；IEC104 通信；告警；写 MySQL；推送给 Qt；内存校验登录 |
| `qt-client` | 五类页面：设备管理、实时监控、告警、历史曲线、操作日志 |

## 核心实体（设备中心）

一切功能围绕 **设备** 及其 **测点**：

1. 设备（配置 + 运行状态）
2. 测点（遥测/遥信/遥控，含 IOA 与限值）
3. 实时数据（内存 + 历史表）
4. 告警
5. 操作日志

详见 [data-model.md](data-model.md)。

## 主站 ↔ Qt 内部通道（建议）

设备链路使用 IEC 104；主站与 Qt 之间使用 **独立 TCP 通道**（可先沿用 `common` 中文本帧，后续可换 JSON），避免把 104 栈绑进 UI 进程。

默认端口（与脚手架 `config_defaults.hpp` 对齐，实现阶段可配置）：

| 端口 | 用途 |
|------|------|
| 2404 | IEC 104（模拟器 ↔ 主站） |
| 5002 | 主站 → Qt 实时推送 |
| 5003 | Qt → 主站（遥控、登录等） |

## 与当前代码的关系

当前仓库为**脚手架**：三端可启动，`common` 含文本 `TELEM` 协议桩。自 [roadmap.md](roadmap.md) **迭代 2** 起逐步替换为 IEC 104 + MySQL，迭代 3 起 Qt 对接主站推送。
